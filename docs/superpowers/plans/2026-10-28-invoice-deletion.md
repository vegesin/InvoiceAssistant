# 发票删除 Implementation Plan

**Goal:** 让邮箱和本地导入的发票支持单张、批量删除及恢复，减少无关材料干扰。

**Architecture:** 以 `invoices.deleted_at` 记录可恢复删除；保留内容指纹、票据身份和原件，沿用既有邮箱去重。删除时解除付款关联，付款截图重新待关联；历史打印记录保留。已删除材料不能编辑、配对、创建报销单或打印。

**Tech Stack:** 现有 Electron／React／SQL.js，不增加依赖。

**Scope:** 卡片“删除”、选中后的“删除所选”、确认弹窗、“已删除”列表及“恢复”。不删除服务器邮件，不提供永久删除。删除前检查打印／报销引用；批量操作全成或全不成。恢复保留人工修正和打印标记，不自动重建旧付款关联。

## Review Focus

- 更改日期、UIDVALIDITY、不同内容同票号、PDF/OFD 变体和历史重复行不得让删除的发票重新出现。
- 删除发票不丢付款截图、不改变已保存打印批次；失败续打遇到已删除发票需先恢复。
- 打印准备、正在打印、状态不确定以及报销单引用必须在修改前检查。
- 批量中有一项不可操作时，其他项也不变；无效、重复和过大选择被拒绝。
- 重启保留删除状态；恢复后可重新配对，不能抢占截图。
