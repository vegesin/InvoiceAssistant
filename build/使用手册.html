使用手册

返回项目首页 · 常见问题 · 资料与隐私

本手册适用于当前 Windows x64 便携版。示例界面和文档图片使用合成材料，不对应真实报销记录。

1. 首次启动

从仓库 Releases 获取便携 EXE，将其放在可写目录后双击。无需安装。首次解压启动可能需要稍等片刻。

首次默认在 EXE 同级创建 InvoiceData/；源码运行时对应项目的 release/InvoiceData/。定位文件使用相对路径 InvoiceData，设置中可以迁移到其他空目录。若默认位置无法写入，软件会提示选择目录。邮箱收取是可选项，只用本地导入也能完成报销材料打印。

已有用户升级时，将新版 EXE 放回原 EXE 所在目录，保留 InvoiceAssistant.private.json 和原资料目录，即可继续使用现有邮箱、日期设置及材料。

2. 先认识两个选项卡

位置 用来做什么
发票报销 发票原件＋实际付款截图的整理、核对、关联、打印
日常开销 日常账单或长截图的交易核算
设置 邮箱、收取日期、自动收取、付款记录排版、资料目录迁移
使用帮助 打开随软件附带的本手册

3. 导入发票

可点击“导入发票”，也可将 PDF、OFD 或 ZIP 拖入“发票报销”页面。ZIP 内的 PDF/OFD 会被提取；普通文本等无关文件不作为发票导入。

  • 同内容文件再次导入会按指纹去重。
  • 识别到相同发票号码的 PDF/OFD 会归为一张，保留原件，优先使用 PDF 预览和打印。
  • 用车行程明细等辅助附件不额外算作一张发票。
  • 只有 OFD 时可保留并解析文字，需要补充同票 PDF 后才能预览和批量打印。

发票卡片按开票日期从新到旧排列；缺少日期时使用接收／导入时间辅助排序。可以搜索商户、金额、日期或发票号码。

删除与恢复发票

卡片下方点击“删除”，或勾选多张发票后点击“删除所选”，核对确认弹窗中的商户、日期和金额后再确认。一次最多删除 200 张；邮箱获取和本地导入的发票都支持。

删除后发票进入“已删除”，不再参与正常列表、配对、合计或新打印。发票原件、PDF/OFD 变体与历史打印记录保留；原付款截图解除关联，回到待关联区。删除不会删除服务器邮件，后续收取、日期范围补扫及同票重复导入也不会自动恢复。

误删时进入“已删除”，找到发票点击“恢复”。恢复保留人工核对字段和已打印标记，付款截图需要重新关联。想重新导入已删除的同一张发票，应先在这里恢复。

打印准备中、正在打印、任务状态不确定或被报销单引用的发票暂不能删除；先完成／确认相关打印任务，或从可编辑报销单中移除。批量操作中任一张不满足条件时，整批不删除。历史失败批次包含已删除发票时，续打前须先恢复发票。

4. 配置邮箱和收取日期

打开“设置”，在邮箱区域填写：

字段 填写方式
显示名称 便于自己识别，如“报销邮箱”
邮箱地址 实际收取发票的邮箱地址
IMAP 服务器 按邮箱服务商的官方客户端说明填写
端口 默认 993，使用加密 IMAP 连接
授权码／密码 按服务商要求使用客户端授权码或允许的凭据

许多邮箱需要先在网页版邮箱中启用 IMAP，再生成独立的客户端授权码。具体入口与规则以服务商当前官方说明为准。需要交互式网页登录授权或额外企业认证的账号，当前版本未必适用。

保存后点击“收取发票”或返回主界面点击“收取邮箱发票”。工具只扫描 INBOX 收件箱，不遍历其他邮件文件夹，也不自动登录邮件正文中的发票下载网站。

日期范围

  • 首次默认从第一次启动当日开始，结束日期留空，表示之后持续收取。
  • 筛选依据是邮件收到的日期，包含起止当天，不是乘车日、开票日或截图日期。
  • 想收取更早的发票：把开始日期改早，保存后再点击收取。
  • 改变范围或接收规则升级时会补扫相应范围，已导入材料继续去重。
  • 开启自动收取后，启动时检查一次，运行期间每 5 分钟检查；退出软件后停止。

邮箱存在邮件但列表没出现时，按常见问题中的顺序排查，不要直接删除配置或数据库。

5. 导入手机实际付款截图

这里需要的是实际付款记录，例如微信、支付宝或银行卡交易详情页。常见格式包括 PNG、JPG/JPEG、WebP、BMP 和 GIF。

将付款截图保存到电脑后，直接拖入工具或点击“导入付款截图”选择文件即可，图片通过何种方式传到电脑不影响导入。也可以复制图片后点击“粘贴截图”。

操作 结果
点击“导入付款截图” 批量导入电脑里的图片
复制图片后点“粘贴截图” 从剪贴板导入图片
拖入页面空白处或右侧截图区 导入待关联截图
单张图片拖到发票卡片 导入并尝试关联此发票
多张图片拖到发票卡片 导入后展示候选，供用户选择
将右侧已有截图拖到卡片 保存该截图与该发票的关联

可选的接收目录

可选的自动接收方式：把已保存图片放入资料目录的 incoming/ 文件夹，运行中的软件会监听并导入，默认作为付款截图。

6. 核对并关联

点击发票或截图预览，打开核对面板；可修正金额、日期、商户、票号等字段，并打开原件或所在文件夹。截图用途选错时，可在核对面板改为“发票付款截图”或“日常开销账单”；已关联的截图先解除关联。

推荐依据金额、商户和日期。相同金额有多笔时，需要看图确认；“采纳高匹配推荐”后也请核对两侧图片。手动修正的字段会保留，后续自动识别不会直接覆盖。

一张付款截图最多关联一张发票。“解除关联”保留原文件，将截图放回待关联区。失败、已取消或全额退款的记录不能直接作为正常付款凭证。

7. 选择打印模式

先勾选发票，再在底部选择打印模式和打印机。打印前可以点击“预览付款排版”。

模式 条件 提交任务
仅打印发票 有可读取的 PDF 即可；金额和付款截图不是前置条件 N 个发票任务
发票＋付款记录 所选发票均已配对有效付款截图 N 个发票任务＋1 个合并付款记录任务

任务统一使用选定打印机、单面、1 份。N+1 指任务数：三张发票加一份两页付款记录，仍是四个任务，但可能打印五张纸。多页原始 PDF 会全部打印。

付款 Word 和排版

付款 Word 为 A4 横向，设置可选每页 2 张或 3 张标准手机截图，保持比例，完整显示。软件同时生成相同纸张和缩放尺寸的 PDF 作为打印内容，因此自动打印不依赖 Word/WPS。

输出在资料目录 export/<批次编号>/，包含付款 Word 与打印 PDF。仅打印发票模式不会生成空的付款 Word。

日常开销长截图不进入此 Word；超过标准手机截图长宽比例的图片需要归入日常开销统计。

失败续打

打开“打印记录”查看每个任务：

  • 已提交：Windows 接收了请求，不等于纸张已成功打印。
  • 失败／待提交：可点击“续打未提交任务”，已成功提交的任务不会自动重打。
  • 状态待确认：超时或程序中断造成状态不确定。先看 Windows 打印队列和实际出纸，再选择“队列中已有”或“确认未提交”。

卡纸、缺纸、离线或驱动问题要先在 Windows 和打印机上处理。建议第一次用少量材料试打，确认页数、方向及单面设置。

8. 日常开销核算

在“日常开销”选项卡导入、拖入或粘贴账单／长截图，勾选本次使用的图片，逐项核对：

  1. 金额是否正确，是否有漏项。
  2. 收支类型是否为支出、退款或收入。
  3. 是否重复截到了同一笔交易。
  4. 是否计入本次核算。

合计为“勾选支出 − 勾选退款”，收入不计入。可手动补充一笔，然后填写核算名称并保存。在“已保存核算”查看历史结果。

改变截图勾选会重新生成明细，建议先选齐截图再修正明细。当前不自动判断不同长截图之间的重复交易。

9. 文件位置、备份、迁移与升级

在设置中可查看并打开资料目录。文件含义详见隐私与资料管理。

  • 备份：退出软件后备份完整资料目录，同时保留 EXE 旁的定位文件。邮箱配置与 .key 必须一起备份。
  • 迁移：停止导入、收取与打印，在设置中选择新的空资料目录。软件校验复制、更新定位并重启，旧目录不会自动删除。
  • 升级：退出旧版，新 EXE 放回原目录，保留定位文件和原资料目录。确认新版能看到材料后，再删除旧 EXE。
  • 分发：只发送公开发布包、使用说明和许可证，不发送自己的定位文件或资料库。

10. 当前边界

仅支持 Windows 10/11 x64。OCR 与匹配需要核对；当前是一张发票对应一张付款截图。OFD 独立渲染、手机端、云同步及企业审批不在当前支持范围。

ZIP 导入和图片、PDF 都设有大小／页数限制；超过限制时请按界面提示拆分。遇到不支持的票据，先保存原件，使用脱敏或合成样本反馈。

常见问题

项目首页 · 使用手册

没有安装按钮，应该如何运行？

当前只提供 Windows x64 便携 EXE，双击即可。源码 ZIP 与便携 EXE 是两种不同下载；源码需要安装开发依赖后构建。

邮箱里有发票，工具却没有显示

依次检查：邮箱账号和 IMAP 是否可用；收到日期是否在设置范围内；邮件是否仍在 INBOX；附件是否为 PDF/OFD/ZIP；是否只有网页下载链接；是否已与同票 PDF/OFD 合并。

把开始日期调早后保存，再点击收取即可补扫，内容去重仍保留。ZIP 接收规则升级也会按原范围重新检查。没有必要为重试删除数据库或重新配置账号。

邮箱提示认证失败

检查邮箱服务商是否启用 IMAP，服务器、端口和授权码是否符合其客户端要求。部分邮箱不允许使用网页登录密码登录客户端。需要额外交互式认证的账号，当前版本可能不适用。请勿把授权码粘贴到 Issue。

发票有金额，但识别为待核对

不同 PDF/OFD 版式、扫描清晰度和字体差异都会影响识别。先打开原件核对，在核对面板手动修正。仅打印发票不要求金额识别成功。反馈时优先附可公开的合成／脱敏样本和格式信息。

机票和高铁票格式是否支持？

支持当前已覆盖的航空行程单和铁路电子客票格式，包括常见 ZIP 附件。航空金额优先取合计，填开日期与航班日期区分。格式变化仍可能需要修正规则，不能视为覆盖所有发行平台和历史票据。

卡片上只有 OFD，无法预览或打印

当前可保存并解析 OFD 文字，未内置独立 OFD 渲染器。请导入同一票据对应的 PDF；识别到相同票号后会归并并优先使用 PDF。

拖入图片没有效果

支持拖入页面空白处、截图区和发票卡片。单图拖卡片可关联，多图导入后需选择。文件应是图片或发票，而非文件夹。

请确认图片已保存到电脑且文件可读取，再从文件资源管理器拖入；也可以点击“导入付款截图”选择文件，或复制图片后点击“粘贴截图”。

为什么相同金额没有自动关联？

同金额多笔交易无法仅凭金额确定。推荐还会比较日期和商户；有歧义时保留给用户看图确认。一张截图不能同时用于两张发票。

邮箱收取的发票可以删除吗？

可以。点卡片“删除”，或勾选后点“删除所选”，确认后移入“已删除”。原件和打印历史保留，付款截图回到待关联区，邮箱中的邮件不受影响。补扫邮件不会让它重新出现；误删可在“已删除”点击“恢复”，然后重新关联付款截图。恢复也会保留已打印标记。

为什么提示发票暂不能删除？

发票可能正在生成打印文件、正在打印、存在状态不确定的打印任务，或仍被报销单引用。按提示先处理相关任务或引用。批量删除会先验证全部选中项，任何一项不满足条件时都不删除。

只有发票，没有付款截图，能打印吗？

可以。在底部选择“仅打印发票”。只要 PDF 可读，不需要先补齐截图、金额或日期。

打印为何是 N+1 任务，却超过 N+1 张纸？

N+1 是 N 个发票文件加一份付款记录文档的任务数。付款文档和原始发票都可能有多页。每个任务均请求单面打印，最终纸张仍受原件页数、驱动和打印机影响。

已提交但没出纸，应该再点一次吗？

先检查 Windows 打印队列和打印机状态。任务可能已排队、缺纸或卡纸。对状态不确定的任务先核对，再在“打印记录”确认，避免重复出纸。

日常长截图为什么不能放进付款 Word？

这两个页面用途不同。付款 Word 使用每张发票对应的标准手机实际付款截图；日常账单长截图用于核对明细和计算合计。将图片用途调整后到相应页面处理。

为什么升级后要求重新配置？

通常应保留 EXE 旁的 InvoiceAssistant.private.json，并确保原资料目录仍存在。若只是把新版 EXE 放到一个空目录，软件可能按新用户启动。先找到原定位文件和完整备份，不要覆盖原资料库。

可以把整个 release 或资料目录发给别人吗？

应按发布指南的公开文件清单分发，不要整个目录打包。当前机器的定位文件、私人配置、密钥、数据库和原件都不属于公开发布内容。

支持 macOS、Linux、手机或企业多人协作吗？

目前发布和验证目标为 Windows 10/11 x64。其他平台、手机端、多人权限隔离和审批流程尚未提供。

隐私与资料管理

项目首页 · 使用手册 · 安全反馈

数据保存在何处

已有用户优先使用定位文件记录的位置。新用户默认使用 EXE 同级的 InvoiceData/；源码运行时对应项目的 release/InvoiceData/，设置中可迁移到其他空目录。开发和自动化测试应使用隔离目录。

EXE 旁的 InvoiceAssistant.private.json 只记录资料位置和首次启动日。它是私人定位文件，不是可公开分发的配置模板。

默认定位值为 "dataRoot": "InvoiceData"，相对于程序所在目录解析，不受启动时工作目录影响。已有外部绝对路径仍兼容。移动便携程序时应将 EXE、定位文件和整个 InvoiceData/ 一起保留；启动时会按资料库记录修正内部文件路径。

资料目录内的位置 内容
config/accounts.private.json 邮箱地址、服务器及加密授权码
config/.key 本地授权码加密所需的密钥
config/settings.json 首次日期、邮箱日期范围、自动收取和排版设置
config/storage.private.json 上次资料位置，用于整体移动后的内部文件路径修正
db/app.db 票据信息、OCR 文本、关联、同步进度、打印任务和日常核算
inbox/<月份>/ 发票原件，同名不同内容保留独立文件
screenshots/originals/ 实际付款截图
expenses/ 日常开销图片
incoming/ 可选的图片接收目录
export/<批次编号>/ 合并付款 Word 和打印 PDF
temp/ 缩略图、邮件暂存和运行缓存

原始文件名和来源信息也可能保存在数据库中。数据库、原件与截图不做全盘加密，均属于应妥善保存的私人资料。

界面中的发票删除采用可恢复方式：保留原件、变体、内容指纹和历史打印记录，仅移入“已删除”并解除付款关联。它不清除磁盘文件，也不删除邮箱服务器上的邮件；“已删除”中的材料仍属于私人资料，需要纳入备份和分发排除范围。

哪些操作会联网

操作 网络行为
收取邮箱发票 使用所配置账号连接对应 IMAP 服务器，当前以只读方式读取 INBOX
OCR、PDF/OFD 解析、匹配、核算 在本地处理，模型随应用附带
打印 提交给 Windows 打印系统；网络打印机的传输由系统和驱动处理
本地图片导入与粘贴 读取用户选择或拖入的图片文件，或在点击“粘贴截图”时读取剪贴板图片；在本地处理

应用未实现业务资料云上传、应用遥测、账号注册或云同步。开发时的 npm 依赖安装和维护者构建下载是另一类网络行为，不代表运行中的 OCR 会上传文件。

本地加密的范围

授权码采用 AES-256-GCM 保存，仍兼容旧版密文迁移。加密配置与密钥分开为两个文件，但通常处于同一资料目录；获得两者及相应文件权限的人能够解密授权码。这不是操作系统凭据库，也不是多用户权限隔离机制。

不要公开实际授权码、密钥、配置、数据库或原始票据。该提示也适用于加密授权码：密文不应成为公开示例。

Git 与公开发布

仓库忽略 *.private.json、.key、运行资料目录、数据库、.qa/、release/ 和 .private-backups/ 等。示例文件使用保留的示例域名，不应改成真实账号。

忽略规则不能撤销已经跟踪或提交的数据。准备公开仓库时，同时检查暂存区和提交历史。若真实授权码曾提交过，应先在邮箱服务商处撤销或更换，再处理仓库历史；仅删除最新文件不等于撤回历史副本。

资料目录若改为仓库内的任意自定义名称，需要把整个自定义目录加入本机忽略规则，或迁移到仓库外。Git 忽略规则不是发布包的文件选择规则；构建还使用独立白名单和发布审计。

备份与恢复

退出软件后备份完整资料目录，包括数据库、原件、截图、accounts.private.json 和 .key。只备份 EXE 不会备份数据；只备份邮箱 JSON 而丢失密钥，不能保证授权码可恢复。

优先通过设置中的迁移功能更改目录，它会复制校验并改写数据库中的路径。手动搬动资料后仅修改定位 JSON，可能留下指向旧位置的绝对文件路径。

移除邮箱账号会保留已导入材料。旧资料目录不会因迁移自动删除，用户需在核验和备份后自行处理。工具退出后不继续收取邮件。

问题反馈时如何脱敏

推荐提交合成样本。若使用真实票据，去掉邮箱、授权码、身份证号、票号、订单号、二维码、地址等识别信息；注意 PDF 隐藏文字层和文件元数据也可能含信息。单纯在截图上盖住文字并不等于 PDF 已脱敏。
