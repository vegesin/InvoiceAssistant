发票报销助手 0.4.0（Windows x64 便携版）

直接运行 InvoiceAssistant-0.4.0-x64-Portable.exe，无需安装。
已有用户自动沿用当前资料位置和邮箱配置，无需重新设置。新用户默认使用 EXE 同目录的“报销资料”，可在设置中迁移，建议将软件放在 D 盘。
软件内置中文 OCR 模型和 PDF 解析组件，无需安装 Python、PaddleOCR、Word 或 PDF 打印插件。

一、发票报销
1. 导入邮箱或本地发票 PDF/OFD/ZIP；ZIP 内的 PDF/OFD 会自动拆包识别，铁路发票不会再因压缩附件漏收。
2. 页面空白区、右侧截图区均支持文件拖入；单张付款图片拖到发票卡片可直接导入并关联，多张图片会导入后供选择。列表按日期从新到旧，点击图片可核对修正。
3. 右侧待关联截图显示缩略图。可拖到发票卡片，也可点击选择截图，查看按金额、商户、日期给出的推荐。
   同金额有多笔时需看图确认。一张截图对应一张发票；分次付款、多张发票共用一笔付款需先人工整理凭证。
4. 勾选发票，选择打印模式和打印机，点击“打印所选材料”。“仅打印发票”不要求付款截图或已识别金额，共 N 个单面任务；“发票＋付款记录”要求配对，共 N+1 个单面任务。
5. 付款 Word 为 A4 横向，每页 2 或 3 张完整手机截图；同时生成同尺寸 PDF 作为软件的打印内容，无需依赖本机 Word。
   付款 Word 与 PDF 均保存在 export/批次编号。可在打印记录里打开 Word。
6. 打印记录保留每个任务的进度。失败可续打未提交任务；超时或程序退出造成状态不确定时，需先核对系统打印队列。
   “已提交”表示 Windows 接收了任务，实际纸张数量、驱动和纸盒情况以打印机为准。
   N+1 是任务数，不保证 N+1 张纸：付款记录可能有多页，多页原始 PDF 也会全部打印。

二、邮箱与日期范围
设置中填写 IMAP 账号和邮箱授权码。开始日期首次默认为首次启动日，结束日期留空表示持续收取。
修改开始/结束日期后点击“收取邮箱发票”，会重新扫描范围，补收历史邮件并去重。升级到本版本会按原有日期范围自动补扫旧 ZIP 邮件，保留原筛选日期。
按邮件接收日期筛选，包含开始和结束当天。程序打开时每 5 分钟检查一次；关闭后不在后台收邮件。
原始附件按内容去重，同票号的 PDF/OFD 合并显示并保留原件。用车行程单等辅助附件不另算一张发票。
只有 OFD 时可保留与识别，但软件批量打印需补充对应 PDF。

三、日常开销
在“日常开销”选项卡导入账单或长截图。支出减退款，收入不计入；明细可改金额、类型、是否计入，也可手动补充。
OCR 可能遗漏、误识别，截图之间可能有重复，请核对后保存核算。日常开销图片不进入付款 Word。

四、微信截图
PC 登录微信不会自动开放聊天记录权限。本工具不解密、扫描微信数据库。
将文件传输助手中的原图保存到电脑，再拖入本软件；也可复制图片后点“粘贴截图”。
如果想由软件监测文件，把已保存图片放进资料目录的 incoming 文件夹即可。

五、资料与私人配置
EXE 同目录的 InvoiceAssistant.private.json 只记录资料位置和首次启动日。
所选资料目录包含：
  config/settings.json              日期范围、排版等设置
  config/accounts.private.json      邮箱与加密授权码
  config/.key                       本地密钥（备份配置时一并保留）
  db/app.db                        发票、配对、打印与核算记录
  inbox/月份/                      发票原件（保留原文件名在数据库中）
  screenshots/originals/           实际付款截图
  expenses/                        日常开销图片
  incoming/                        可选图片接收文件夹
  export/批次编号/                  付款 Word 与打印 PDF
  temp/                            缩略图、邮件暂存和运行缓存
新数据不默认写进 C:\Users\用户名\AppData\Local\InvoiceReimbursementAssistant。
发现旧版资料时可选择复制迁移；复制会校验，旧目录保留。确认迁移与备份后，可自行处理旧目录。
设置内可迁移到另一个空资料目录并重启，原资料不自动删除。

分发给他人只发 Portable.exe 和本说明即可，不要发送自己的资料目录、私人 JSON 或密钥。
便携 EXE 未作商业代码签名；首次解压启动会比后续启动慢。
第三方组件及模型的许可证保留在软件资源中的依赖包内，详见项目 build/第三方组件说明.txt。
